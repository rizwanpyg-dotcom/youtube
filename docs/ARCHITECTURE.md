## 1. Design principles

1. **$0 and no card.** Every component is free. No Google Cloud billing account is ever linked, so paid usage can't happen by accident.
2. **The PC stays off.** All scheduled work runs on GitHub-hosted runners. The PC is used once, for OAuth bootstrap.
3. **Stateless compute, durable state.** Runners are disposable. The SQLite DB lives on a git `state` branch, so every change is versioned and recoverable.
4. **One video per job.** A job takes one video from its current stage as far as it can, so large media never needs to persist between runs.
5. **Idempotent everything.** Each unit of work has an idempotency key. Re-running a workflow never duplicates a topic, video or upload.
6. **Evidence before prose.** The script may only state facts that exist as verified claims, with quotes that literally appear in a fetched source.
7. **Humans gate trust and money.** Approval is required for spending, account and policy actions, and for videos during the supervised launch.

## 4. The pipeline as a state machine

Each video row moves through `videos.stage`. `videos.status` says whether it may move (`active`), is blocked on a person (`waiting`), or has stopped (`paused`/`failed`/`rejected`/`done`).

```
planned ─▶ researched ─▶ fact_checked ─▶ scripted ─▶ [script_approval]* ─▶ voiced ─▶ visuals_ready
   ─▶ rendered ─▶ thumbnailed ─▶ seo_ready ─▶ qc_passed ─▶ [final_approval]* ─▶ package_ready | scheduled ─▶ published

* approval gates are on during the supervised launch (settings.require_*_approval)
```

| Stage transition | Agent | Persisted output | Main failure modes |
|---|---|---|---|
| → planned | 2 Topic | `topics`, `calendar`, `videos` row | duplicate topic (UNIQUE slug + fingerprint check) |
| → researched | 3 Fact-check (gather) | `sources`, draft `claims` | source fetch failure (retry), too few tier 1–2 sources (reject topic) |
| → fact_checked | 3 Fact-check (verify) | `claims.status`, `claim_sources` | < 12 verified claims (reject topic) |
| → scripted | 4 Script | `scripts` v1..n | QC script fail (rewrite, max 3 versions) |
| → script_approval | owner | `approvals` (Issue) | changes requested (new version) |
| → voiced | 5 Voice | WAV (ephemeral), sentence timings in `result_json` | loudness/silence QC |
| → visuals_ready | 6 Video | scene plan + `assets` licence rows | asset with no licence → swap or chart |
| → rendered | 6 Video | MP4 (ephemeral), `render_seconds` | ffprobe/blackdetect QC |
| → thumbnailed | 7 Thumbnail | `thumbnails` A/B/C | — |
| → seo_ready | 8 SEO | `seo_metadata` | metadata length/claim checks |
| → qc_passed | 10 QC | `qc_reports` (final) | score < 0.85 → back to the failing stage |
| → package_ready / scheduled | 8 Publisher | artifact link or `youtube_video_id` | quota, upload error (resumable retry) |
| → published | 8 Publisher (status poll) | `published_at` | — |

**Ephemeral media.** Stages from `voiced` to `package_ready` run inside **one job** (~20–50 min estimated [ASSUMPTION]), so WAV/PNG/MP4 never have to survive between jobs. If that job fails midway, the next run regenerates media from the saved text state (script, scene plan, asset list) in the DB. That is deterministic and costs nothing.

**Approval waits never block the queue.** A `waiting` video is skipped, and the next active video is processed.

### Task queue semantics (`tasks` table)
- **Idempotency key:** `video:{id}:{stage}:v{script_version}`. Inserting an existing key is a no-op.
- **Lease:** a task is claimed with `status='running', lease_until=now+90min`. The watchdog resets expired leases to `pending`.
- **Retry:** exponential backoff of 10 min × 3^attempt. After `max_attempts` the task is `dead` and appears on the dashboard and as a GitHub Issue.
- **Concurrency:** every DB-writing workflow uses `concurrency: {group: state-db, cancel-in-progress: false}`, so only one writer exists at a time. That makes SQLite on a git branch safe.

### Duplicate prevention (layers)
1. `topics.slug` UNIQUE, plus a fingerprint Jaccard check above 0.6 against all topics.
2. One long-form video per topic (partial unique index).
3. `tasks.idempotency_key` UNIQUE.
4. `videos.youtube_video_id` UNIQUE. Before uploading, the publisher writes a pending marker; after a crash it searches the channel's own uploads for the marker before retrying.
5. Script similarity to all past scripts must be ≤ 0.20 (word-trigram Jaccard).

## 5. Agents: contracts

All LLM calls go through `llm/router.py`. Calls request **JSON matching a schema**, are validated, are retried up to 2 times, then fall back to the next provider. Factual tasks use temperature 0.1.

### Agent 1: Market research (monthly, plus on demand)
- **In:** seed keyword lists per sub-category (bank panics, currency crises, failed tech standards, bubbles, corporate frauds, industrial decline).
- **Method:**
  - YouTube `search.list` (≤15/day × 100 units [REPORTED cost]) plus `videos.list` (1 unit) for the top 20 results per query.
  - Demand = median views/day of results under 3 years old.
  - Competition = share of results from channels with more than 500k subscribers.
  - Gap = demand ÷ (supply of recent results), with an extra point when the best result is more than 3 years old.
- **Out:** `niches` scores with `evidence_json` holding the raw numbers, so the dashboard shows the evidence, not just the verdict.
- **Rule:** it may recommend a niche change but **never applies one**. A change is a `policy` approval for the owner.

### Agent 2: Topic research (daily; keeps the backlog at 20 or more candidates)
- **Sources:**
  - LLM brainstorm restricted to the niche taxonomy.
  - Wikipedia category crawls (e.g. "Economic crises", "Defunct companies").
  - Anniversaries in the next 60 days ("100 years since…").
- **Scoring:** `final = 0.35 demand + 0.25 gap + 0.15 evergreen + 0.15 source_availability + 0.10 bandit_bonus(category)`.
- Source availability is checked before a topic is accepted: at least 3 tier 1–2 sources must exist.
- **Calendar:** fills `calendar` slots `production_lead_days` ahead, and avoids the same category twice in a row.

### Agent 3: Fact-checking (anti-hallucination core)
1. **Gather.** Fetch 8–20 sources (Wikipedia, used as a map to its own references; FRED/World Bank for numbers; EDGAR filings; archive.org public-domain texts; reputable press). Store each source's text hash and a cached excerpt, and give it a credibility **tier**.
2. **Extract.** The LLM proposes atomic claims (number, date, quote, event, causal), and each one must carry an `evidence_quote` copied from a source.
3. **Verify (deterministic).** Code checks that each `evidence_quote` appears in the fetched text (normalized whitespace/case, fuzzy ratio ≥ 0.95). If it doesn't, the claim is rejected. This catches invented quotes and numbers without trusting the LLM.
4. **Corroborate.** A claim becomes `verified` only with 2 independent supporting sources, or 1 tier-1 primary source (official data, filing). Contradicting evidence makes it `conflicting`. The script may mention a conflicting claim only as "sources disagree".
5. **Hard rules:**
   - Every direct quotation needs a tier 1–2 source.
   - No statistic without a dated source.
   - Fewer than 12 verified claims means the topic is rejected as "insufficient evidence".

### Agent 4: Scriptwriting
- **Target:** 1,350–1,900 words for long-form (~9–13 min at ~150 wpm), or 110–140 words for a Short.
- **Two passes.** Pass 1 is an outline: hook (≤ 30 s, opening on a concrete scene or number), stakes, 4–6 acts, "why it matters now", close. Pass 2 is the narration. Every factual sentence carries `[C#]` claim markers, and the text contains `[SCENE: chart|map|image|card]` cues.
- **Style rules:** banned-phrase list (generic AI filler such as "delve", "in today's video", "buckle up"), no invented dialogue, no advice ("you should invest…"), sentences under 30 words for speech.
- **Self-check by code:**
  - All `[C#]` markers point to verified claims.
  - Sentences containing digits, years or quotes must have a marker.
  - Similarity to past scripts is ≤ 0.20.
- **Description:** the source list goes into the description with numbered references.

### Agent 5: Voice production
- Kokoro-82M on CPU, one consistent voice. **Each voice's licence must be confirmed from VOICES.md before launch** [action item]. Piper is the fallback.
- Audio is synthesized **per sentence**, which gives exact timings for captions and scene cuts and lets a single bad sentence be retried.
- **Post-processing:** silence trim, 180 ms pause between sentences, FFmpeg `loudnorm` to −14 LUFS integrated / −1 dBTP.
- **Pronunciation dictionary** (`config/lexicon.yaml`) for names, currencies and dates.
- **QC:** duration within ±10% of the estimate, no clipping, no silence longer than 1.5 s.

### Agent 6: Video production
- **Scene planner:** maps `[SCENE]` cues to sentence spans (4–12 s each).
- **Visual types,** all original or properly licensed:
  - *Data charts* (matplotlib in brand style) from FRED/World Bank/source tables, with progressive reveal rendered as frame sequences. **This is the signature format.**
  - *Maps* (Natural Earth, public domain).
  - *Archival images* (Wikimedia Commons/LoC, PD/CC0/CC-BY(-SA) only; licence read from the Commons API and stored in `assets`; NC/ND are blocked by a DB constraint).
  - *Typographic cards* (quotes with attribution, timelines, key numbers).
- **Motion:** Ken Burns pan/zoom on stills, a 0.4 s crossfade between scenes, subtle grain and vignette for a consistent look.
- **Audio mix:** narration plus a music bed at −26 dB with sidechain ducking. Music only from `assets/music/licences.json`.
- **Captions:**
  - Long-form: SRT built from sentence timings, uploaded as a caption track (`captions.insert`).
  - Shorts: captions burned in, large and centred.
- **Encode:** H.264 High, CRF 20, `veryfast`, yuv420p, AAC 192k, `+faststart`. Shorts are 1080×1920.
- **Shorts** are cut from the long-form material (the strongest single fact, 35–58 s) and link to the full video. They are a trailer, not a template clone.

### Agent 7: Thumbnail and branding
- Pillow renders 1280×720 PNGs (< 2 MB) in three style families: `chart-crash`, `headline-dark`, `map-focus`. Text is 3 words or fewer and comes from verified facts.
- **Honesty check:** the thumbnail text must appear in, or follow from, the title and a verified claim.
- **Testing:** YouTube's built-in thumbnail A/B test isn't exposed in the public API [ASSUMPTION]. So the style is chosen by a Thompson-sampling bandit across videos, and the result is learned from per-video CTR when available.

### Agent 8: SEO and publishing
- **Keywords:** YouTube search suggestions (the public suggest endpoint [ASSUMPTION: free, unofficial; fall back to LLM plus Agent 1 data if blocked]).
- **Title:** ≤ 70 characters, must not overclaim (checked against claims). Two candidates; the bandit picks the pattern.
- **Description:**
  - Summary.
  - Chapters from act timestamps (first chapter at 0:00, at least 3 chapters, each ≥ 10 s).
  - "Sources" with numbered references.
  - "Credits" with every CC-BY attribution.
  - AI-use statement: "Narration voice is AI-generated; research is source-verified."
- **Flags:**
  - `categoryId=27`.
  - `selfDeclaredMadeForKids=false`.
  - Altered/synthetic flag **on** whenever a realistic generated image is used. The API field name (`status.containsSyntheticMedia`) needs confirming [ASSUMPTION].
- **Publish modes** (`settings.publish_mode`):
  - `package` (until the API audit passes): the MP4, thumbnail, SRT and `metadata.txt` are uploaded as an Actions artifact, and a GitHub Issue gives the owner a 2-minute checklist for uploading in Studio.
  - `review_window` (after the audit): upload as private with `publishAt` = slot; the owner can watch the private video and comment `/reject` before the slot.
  - `auto`: same as `review_window`, with no notification. Enabled only by the owner after 15 or more supervised videos pass.
- **Quota:** each upload is pre-checked against `api_usage`. Cost per video ≈ insert ~100 (≤ 1,600 [REPORTED]) + thumbnails.set 50 + captions.insert ~400 [ASSUMPTION] ≈ 0.6–2.1k units, inside the 8,000/day self-cap.

### Agent 9: Analytics (daily 06:00 UTC)
- **YouTube Analytics API:**
  - Per video, per day: views, estimatedMinutesWatched, averageViewDuration, averageViewPercentage, likes, comments, subscribersGained/Lost.
  - Channel: subscribers, views.
- **Limitation:** impressions and CTR may not be available through the Analytics API [ASSUMPTION]. The columns stay NULL if so, and the bandit falls back to views-per-impression proxies (views in the first 48 h).
- **Learning loop:** at day 7 and day 28 each video gets a reward of `0.5 × percentile(views_7d) + 0.5 × percentile(avg_view_pct)`, which updates `strategy_arms` (category, length bucket, thumbnail style, title pattern).
- Insights are written as plain sentences with evidence, e.g. "bank-panic topics retain 9 points better (n=6)".
- **Guard:** no strategy change is applied until a dimension has at least 4 videos; before that, insights are shown but not acted on.
- **YPP tracker:** subscribers versus 1,000; public watch hours over 365 days versus 4,000; Shorts views over 90 days versus 10M (`v_monetization`).

### Agent 10: Quality control (gate at every stage; final score ≥ 0.85)
| Gate | Automated checks |
|---|---|
| research | ≥ 12 verified claims; ≥ 3 tier 1–2 sources; all quotes verified |
| script | word count; 100% of factual sentences cited; banned phrases = 0; similarity ≤ 0.20; no advice phrasing; LLM critic pass (hook, clarity, flow) with scores |
| audio | duration ±10%; −14 ±1 LUFS; no clipping; max silence 1.5 s |
| video | ffprobe resolution/fps/codec/duration; `blackdetect`/`freezedetect` within limits; A/V duration difference < 0.2 s; every scene has an asset with a recorded licence |
| thumbnail | 1280×720, < 2 MB, text ⊂ title/claims |
| metadata | lengths; chapters valid; sources and credits present; AI statement present |
| final | weighted score ≥ 0.85, else the video is sent back to the weakest stage (max 2 loops), then `failed` with a reason |

## 6. Workflows (GitHub Actions)

| Workflow | Trigger (UTC) | Does | Writes DB |
|---|---|---|---|
| `pipeline.yml` | cron `17 */4 * * *` + manual | `plan` (top up topics/calendar) → `produce` (advance up to 1 long or 2 Shorts) → `publish` (due packages/uploads) → `export` | yes |
| `control.yml` | `issue_comment`, `issues: labeled`, manual | applies `/approve`, `/reject <reason>`, `/changes <notes>`, `/pause`, `/resume`, `/retry <task>` **only if the author is the repo OWNER** | yes |
| `analytics.yml` | cron `0 6 * * *` | Agent 9, learning update, dashboard export | yes |
| `watchdog.yml` | cron `40 */6 * * *` | reclaims stale leases; checks last successful run < 8 h, quota headroom, disk, DB integrity; opens an Issue on failure (emails the owner); commits a heartbeat | yes |
| `backup.yml` | cron `0 3 * * 0` | `VACUUM INTO`, gzip, attach to a `db-backup-YYYY-WW` release, keep 12 | no |
| `pages.yml` | push to `gh-pages` | deploys the dashboard | no |

- All writers share `concurrency: state-db`.
- The job timeout is 120 min, with a safety margin below the runner's 6 h limit [ASSUMPTION].
- **State checkout:** `git fetch origin state`, then work on `youtube_automation.db`, then `PRAGMA integrity_check`, then commit and push. If the push is rejected, the job fetches, re-applies (the queue is idempotent) and pushes again.
- **60-day disable risk:** the heartbeat commit plus the regular state commits count as activity [ASSUMPTION, tested in Phase 5]. The watchdog also opens an Issue if no pipeline run has happened in 3 days.

## 7. Dashboard

- **Hosting:** static site on GitHub Pages (`gh-pages`). It's **public** because the repo is public, so it shows only sanitized data: no secrets, no OAuth info, no raw error traces (errors are redacted and truncated).
- **Data:** `export` writes `data/*.json`: pipeline, calendar, research queue, scripts (status only), failed tasks, analytics, YPP progress, costs, API quota, health, and recent runs.
- **Panels:**
  - Overview: health light, today's quota, next slot, cost this month ($0.00).
  - Pipeline Kanban by stage.
  - Content calendar.
  - Research queue with scores and evidence.
  - Approvals waiting, each linked to its Issue.
  - Failed and dead tasks with Retry links.
  - Performance charts.
  - YPP progress bars.
  - Infrastructure: run durations, render time per video, runner disk and RAM peaks.
- **Controls:**
  - A static page can't write safely, so each control is a **link that opens a pre-filled GitHub Issue comment or a workflow_dispatch page**.
  - The control workflow verifies that the actor is the owner before acting, because on a public repo anyone can comment.
  - Pause/resume, approve/reject, retry and "produce now" all go through this path.

## 8. Security design

| Threat | Control |
|---|---|
| Credential leak in code/logs | Secrets only in GitHub Actions Secrets (`GEMINI_API_KEY`, `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`); GitHub masks them in logs [VERIFIED behaviour of Actions secrets]; our `log.py` also redacts token-shaped strings; the DB has no secret columns; `.gitignore` blocks `*.json` client secrets/tokens |
| Strangers controlling the bot via Issues | `control.yml` acts only when `author_association == 'OWNER'`; all other comments are ignored and logged |
| Malicious PRs stealing secrets | No `pull_request_target`; PR workflows from forks get no secrets; Actions are pinned to commit SHAs; branch protection on `main` and `state` |
| Token over-privilege | Workflow `permissions:` minimal per job (`contents: write` only where the DB is committed; `issues: write` only for control/watchdog); OAuth scopes limited to `youtube.upload`, `youtube.force-ssl` (captions/thumbnails), `yt-analytics.readonly` |
| OAuth token expiry | OAuth app set to "In production" (Testing-mode refresh tokens expire after 7 days [ASSUMPTION]); the watchdog checks token validity every 6 h and opens a "re-authorise" Issue |
| Runaway costs | No billing account; per-provider daily caps in `api_usage`; `expenses` CHECK blocks any amount > 0 without `approved_by` |
| Account ownership/AdSense/policy actions | Never automated; always an owner task |

## 9. Reliability, backups and recovery

- **Logging:** JSON logs to stdout (kept by Actions) plus a `WARNING`+ summary in the `events` table. Retention: events older than 90 days are pruned.
- **Retries:**
  - HTTP calls: 3 tries with jittered backoff; 429 honours `Retry-After`.
  - Uploads: resumable upload sessions.
  - Pipeline tasks: queue-level retry (section 4).
- **Backups:**
  1. Every state commit is a point-in-time version (git history).
  2. A weekly `VACUUM INTO` snapshot is released as an asset, 12 kept.
  3. The monthly analytics CSV export goes into the release too.
- **Storage management:**
  - Runners start clean.
  - Artifacts expire after 14 days.
  - The DB is expected to stay under 50 MB per year [ESTIMATE]; when it passes 100 MB, `events` and old `sources.excerpt` are archived.
- **Health checks:** last-success age, dead-task count, quota headroom, OAuth validity, DB integrity, the 60-day activity guard.
- **Recovery runbook** (full version in Phase 5 docs):
  - *Corrupt DB:* restore the previous `state` commit (`git revert`), or the latest release backup.
  - *Stuck video:* `/retry` or `/reset-stage <id> <stage>`.
  - *Token revoked:* run `scripts/oauth_bootstrap.py` on the PC and update the secret.
  - *Workflows disabled:* re-enable in the Actions tab.
  - *Provider limit cut:* change `config/channel.yaml` provider order.

## 10. Content strategy and compliance built into the design

- **Cadence:**
  - Launch at 2 long-form + 2 Shorts per week.
  - Shorts go to 3 per week only after 8 long-form videos pass QC with average view percentage ≥ 35% [DESIGN threshold, to revisit with data].
  - Quantity never rises automatically; it's an owner approval.
- **Originality:** every video is built on its own researched claim set and its own data visuals, and a similarity cap blocks near-duplicate scripts. This is the main defence against the inauthentic-content policy.
- **Copyright:** only licences from the allow-list; every asset is registered with a source URL and attribution; no third-party footage; no music outside the cleared folder.
- **Disclosure and honesty:**
  - AI narration is disclosed in every description.
  - The synthetic-media flag is set where it applies.
  - Thumbnails and titles are checked against verified claims.
- **Never automated:** AdSense, identity verification, copyright disputes, account security, spending, niche change, raising the cadence.
